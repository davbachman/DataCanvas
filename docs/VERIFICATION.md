# Verification and limits

Verified on October 1, 2026 in Linux x64 with Node 24.19.0 and Chromium 151.0.7922.173. Browser and native adapters report DuckDB v1.5.4. Dependencies are pinned in the lockfile.

## Automated coverage

- **37 unit/integration tests**: missing and empty-table semantics; count variants; arithmetic; deterministic sampling; join multiplicity and key behavior; pivot drift; parse/correction failures; immutable assets and archive safety; explicit source replacement; stable references; dependency/cache invalidation; isolated SQL; chart populations; timestamp microseconds and large integers; RE2 flags, captures, replacement, invalid patterns, missing values, and portable settings; column-name selection with dynamic schemas, empty inputs, zero visible columns, lineage, and version compatibility.
- **11 browser scenarios** (33 CI executions across Chromium, Firefox, and WebKit): production `/DataCanvas/` asset/worker loading; import → recipe → chart → portable backup → fresh-context reopen; keyboard/list operation controls and undo/redo; IndexedDB recovery; Step/Run and real worker cancellation; isolated SQL; mark lineage and explicit selection recipes; seven chart families, layers/facets, light/dark laptop layouts; report HTML export; regex preview/filter/extraction; column-name pattern keep/drop, preview, and saved-project reopening; and four browser/native parity fixtures.
- Parity compares typed schemas and values, duplicate multiplicity, row counts, authored chart specifications, and computed statistical tables. Decimal aggregates use an explicit absolute tolerance of `1e-12` to accommodate floating-point summation order. Text, integers, dates, and timestamps remain exact. Adversarial fixtures include a capture/replace/filter regex chain.
- `npm run build` type-checks and creates the deployable static build. CI repeats semantic tests, the production build, and browser tests before deploying.

Tests use explicit expected values and independent small calculations, not just SQL snapshots. Run with `npm test`, `npm run build`, and `npm run test:browser`. Playwright screenshots/traces are generated in the ignored `test-results` directory.

## Visual review

Reviewed the workbench, table inspector, chart editor, and report at 1440 × 900; reviewed 1280 × 800 light/dark workspaces and layered/faceted plots. The bottom inspector can be resized or maximized; narrower layouts expose pane tabs. Blockly uses actual typed snapping connections and has a synchronized list editor. Forms have labels and list controls avoid requiring drag gestures. A full screen-reader audit has not been performed.

## Performance

Measurements are single observations on a shared AMD EPYC 9V74 environment with five logical CPUs exposed, not laptop guarantees. The fixture contains 100,000 rows × 20 columns, a 20-operation main pipeline, a 10,000-row lookup, and summary/sample branches. Source parsing, full-data profiles, diagnostic queries, and lineage are included.

See the checked-in [native measurements](benchmark-native.json) and [Chromium measurements](benchmark-browser.json), generated by `npm run benchmark` and `node scripts/benchmark-browser.mjs`. The latter requires the former's `/tmp/data-canvas-benchmark.datacanvas` and the production subpath server.

Native measurements: cold database startup **12 ms**, first full pipeline **4.10 s**, warm query **2 ms**, cached repeat **52 ms**. Native RSS grew from approximately **316 MiB to 749 MiB**, including JavaScript/native runtime overhead; the DuckDB memory budget is not a total-process RSS cap. Chromium completed the cold full worker run in **24.91 s** (engine work **24.00 s**) with **497** main-thread 50 ms timer ticks, confirming UI-thread availability during computation. Reported main-thread JavaScript heap grew from **30.7 MiB to 38.2 MiB**; this excludes worker/native memory.

## Known limitations

- Local browser checks use installed Chromium because this environment blocks browser downloads. The GitHub Pages workflow installs and tests Chromium, Firefox, and WebKit; its status is the release gate. WebKit on Linux is not a test of Safari on an actual Mac/iPhone, and mobile-device behavior remains unverified.
- The complete cold 100,000-row pipeline exceeds a two-second interaction target. Cached runs are substantially faster; workers keep queries off the UI thread. Wasm startup and source parsing remain material costs.
- The bundled DuckDB Wasm is approximately **41.3 MB uncompressed / 9.36 MB gzip**. First-load speed depends on network caching/compression. There is no service-worker offline-install guarantee.
- Table inspectors default to 100 preview rows; full statistics are computed before previewing. Raw chart display is capped at 20,000 rows and statistical chart tables at 10,000 rows; oversized displays error rather than silently sample. Headless/source limits default to one million rows. ZIP limits are 64 MiB compressed and 256 MiB expanded.
- Numeric “decimal” storage is DOUBLE, not arbitrary-precision decimal. Signed 64-bit integers preserve exact values in tagged outputs; timestamps preserve microseconds in UTC.
- SQL supports an intentionally restricted parsed SELECT/WITH subset and only explicitly bound copied tables. Approximate comparison can be expensive for large unmatched duplicate bags. There is no SQL-to-block round trip.
- Range brushing is available for single-layer, unfaceted scatter/line plots. Mark inspection and contributor-based predicates cover the other supported families. Unsupported disconnected scratch blocks are reattached to the recipe rather than stored as executable fragments.
- RE2 does not implement lookaround or pattern backreferences. Replacement capture references use `\1`–`\9`. Regex operations currently target one column each; chain operations for multiple columns/captures.
- CLI memory settings constrain the DuckDB budget and JavaScript heap independently; callers needing a hard total-memory ceiling must provide OS/container isolation. See the [integration contract](INTEGRATION.md).

See the [Pages workflow](https://github.com/davbachman/DataCanvas/actions/workflows/pages.yml) for the exact commit’s cross-browser results, deployment status, and published-asset verification. Accessibility and performance qualifications above remain applicable.
