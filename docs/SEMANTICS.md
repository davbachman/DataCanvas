# Data Canvas semantics 1.0.0

- Storage types: text, Boolean, signed 64-bit integer, decimal/real (DuckDB DOUBLE), date, timestamp. Analytical roles are independent. Dates are calendar dates; timestamps use UTC. Exact arbitrary-precision decimal storage is not currently a separate UI type.
- Stable column IDs carry references. Rename changes labels, not identities. Derive/summary produce new IDs. Joins namespace each left/right occurrence, including self-joins. Missing columns cause errors; names never silently rebind a reference.
- Sources retain bytes, import settings, SHA-256, and raw text. Imported numbers use explicit typed casts. Failures produce null plus diagnostics; Parse preserves source text and reports examples. Literal `NA` is not implicitly missing.
- Tables are unordered unless explicitly sorted. Sort has ordered key fields, directions, null placement, and stable source-row-ID tie breaking. Grouping, joins, pivots, append, and sampling clear analytical ordering.
- Comparisons with null normally yield unknown. Filter retains only true and separately counts false and unknown. Use `is_missing`/`not_missing`; equality with null is not a missing test. Literal text matching is exact and case-sensitive. The regular-expression operation uses RE2 with explicit case/multiline/dot-all settings; see [regex semantics](REGEX.md).
- Join keys containing null do not match. Composite equality keys are conjunctive. Left/inner/full/semi/anti joins have SQL bag semantics. Multiplicity and unmatched counts are exact. Join guards stop before materializing an oversized result.
- Append matches by exact column name and compatible storage type, never by position. Union mode explicitly fills absent fields with null.
- Missing group fields form visible groups. `count` counts rows, `count_valid` counts nonnull values, `count_missing` counts nulls, and `distinct` counts distinct nonnull values. Numeric aggregates ignore missing and disclose valid counts. Empty numeric aggregates, including sum, yield missing. Sample SD requires at least two values.
- An ungrouped empty summary produces one count-zero row; a grouped empty summary produces no groups. Proportion exposes numerator and denominator separately and evaluates its numerator within the specified denominator population.
- Arithmetic promotes to DOUBLE. Division/modulo by zero, invalid square-root/log domains, and nonfinite arithmetic become null. Diagnostics report missing derived values; they can include missing inputs as well as invalid arithmetic.
- Quantiles use continuous linear interpolation. Box plots use Q1/Q2/Q3 at .25/.5/.75; whiskers reach the most extreme observed values within 1.5 IQR. Outliers remain available in contributing records.
- Histogram bins have explicit positive width, anchor zero, and closure `[start,end)`. Every finite extreme has a bin. All statistics use the complete recipe output before display limits. Count bars visibly expose counts; explicit-value bars do not aggregate implicitly.
- Lines sort x within color/detail groups. Missing y breaks paths; missing x cannot be positioned and is disclosed as omitted. Log scales omit and report nonpositive values. Bars default to zero baselines.
- Sampling uses `md5-rank-v1`: sort by MD5(seed concatenated with stable row ID), break hash ties by row ID, and take the requested count or floor(fraction × population). Sampling is without replacement and independent of engine row order. Source replacement can change row identities; fingerprints make that dependence explicit.
- Deduplication requires specified columns and an explicit order. Stable row identity breaks ties. Keyed corrections require exactly one match, the expected old value, and an explanation.
- Pivot longer keeps unselected identifiers and missing values by default. A variable field supplies source-column context. Pivot wider rejects duplicate cells unless an aggregation is selected. Output IDs incorporate operation ID and the UTF-8 category identity; schema drift cannot redirect a disappeared category's reference.
- Required checks alter no rows and never prevent saving/exporting computed results. They prevent a passed-check status. A failed operation has no current output; dependent recipes are blocked. Generation IDs prevent obsolete worker responses from replacing newer results.

The browser and native Linux paths both use DuckDB **1.5.4** and the same compiler. Tests compare actual results, not SQL similarity. Engine packages and application semantic versions are independent; see the lockfile and result manifest.
